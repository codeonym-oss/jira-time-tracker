# jtt init

Choose, for each project, the field that holds the estimate and what its numbers mean.

![jtt init: skipping a project, choosing a story points field and a time tracking field](gifs/init.gif)

```console
$ jtt init
```

For each project you can see and have not set up yet, `jtt init` lists the site's numeric
fields. The fields on one of the project's create screens are marked ★ and come first. Answer
with the field's number, `s` to skip the project, or `q` to stop; each project is saved as soon
as it is answered.

Then say what the field's numbers mean: `points`, or a time unit (`seconds`, `minutes`,
`hours`, `days` or `weeks`). For a time unit, also choose the unit reports show. Jira's own
time tracking fields always hold seconds, so for those only the display unit is asked. Your
previous field is offered as the default for the next project.

The first project set up becomes the default one, used whenever `-p` is left out.

## Without the questions

Give the field, and `jtt init` asks nothing:

```console
$ jtt init -p WEB --field customfield_10028 --unit points
$ jtt init -p OPS --field timeoriginalestimate --display-unit days
```

[`jtt fields`](fields.md) lists the field ids. With `-p`, `init` sets up those projects even
when they already are; `--reconfigure` revisits every project:

```console
$ jtt init --reconfigure -p DEMO
```

## Options

```text
jtt init [OPTIONS]
```

| Option | Default | Description |
|---|---|---|
| `-p`, `--project` `TEXT` |  | Only these projects (repeatable). Default: every project you can see. |
| `--field` `TEXT` |  | Field id to use without asking, e.g. customfield_10016. |
| `--unit` `[points\|seconds\|minutes\|hours\|days\|weeks]` |  | What the field's numbers mean (with --field). |
| `--display-unit` `[points\|seconds\|minutes\|hours\|days\|weeks]` |  | Time unit reports use (with --field). |
| `--reconfigure` |  | Also revisit projects already configured. |
| `-h`, `--help` |  | Show the command's help and exit. |
